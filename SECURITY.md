# Security Policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Contact the repository owner privately and include:

- The affected route, action, or component
- Reproduction steps or a minimal proof of concept
- Expected and observed behavior
- Potential impact
- A suggested remediation, if available

Do not include real participant records, credentials, storage keys, session tokens, or other sensitive data. Use synthetic test data.

## Supported version

Security updates are applied to the current default branch. Deployments should track tagged or commit-pinned releases and run the checks in `docs/DEPLOYMENT.md` before promotion.

## Disclosure

Allow maintainers reasonable time to investigate and release a fix before public disclosure. Coordinate disclosure timing with the repository owner.
